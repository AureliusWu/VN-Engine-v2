# v1.4.1 Studio 候选试玩验证

日期 2026-11-06。基线 `020cbd913231a4c641addeb211c779d12d929adb`，自研引擎开发版本 1.4.0。开源与社区对照、实施范围和验收口径见 [升级计划](PLAN-v1.4.1.md)。

## 性能

同一 Windows x64、Node 24.14.0、Chromium 153.0.8010.12 和 1360×1000 视口。两侧均用真实未包装 Worker、同一 7000 行及 7000 cue 夹具，源 SHA256 为 `a420507a744229ae037b1d2c596bc28ce2f48866cd11481a9aeb346ecca45886`。固定各三轮，分别观察候选状态、iframe 同 revision 回执、实际对白及两次 rAF。表中各值为中位 / 最慢，单位毫秒。

| 指标 | 1.4.0 | 1.4.1 | 中位变化 |
| --- | ---: | ---: | ---: |
| 点击到绘制机会 | 30.8 / 31.4 | 31.0 / 31.5 | +0.6% |
| 点击到候选就绪 | 258.2 / 261.5 | 180.3 / 186.4 | −30.2% |
| 候选构造与预检 | 32.0 / 33.2 | 15.5 / 15.9 | −51.6% |
| 刷新状态到 iframe 接收 | 70.2 / 74.1 | 61.5 / 62.2 | −12.4% |
| 点击到 iframe 就绪 | 372.8 / 374.5 | 262.5 / 271.0 | −29.6% |
| 点击到首帧代理 | 384.0 / 385.4 | 270.6 / 282.1 | −29.5% |
| 主线程心跳最大间隔 | 152.4 / 154.2 | 91.0 / 92.9 | −40.3% |

新三轮未观测到 50ms 以上的 Long Task。消息段包含准备、序列化、排队与接收成本。首帧代理依据同 revision 回执确认对白后等待两次 rAF。首批探针漏记首帧，保留该批原始失败，修正探针后两侧采用相同口径。本次与 v1.4.0 历史 Playwright wall 测量口径有差别，改进率以本轮基线为准。三轮样本适用于该本机夹具。

原始报告为 `test-results/v141-baseline-performance.json`、`v141-after-performance.json`、`v141-initial-probe-failure.json` 和 `v141-performance-comparison.json`。专项首次运行证据抓取的单次点击到状态 wall 已单列，包含浏览器自动化与报告展示开销，未并入上述启动对照。

重建校园样例包后，玩家 68 份 lib JS 合计 423183 B，逐文件 gzip 合计 121174 B，与基线相同。Studio 的作者 JS/CSS 加 lib JS 合计 778486→779139 B，逐文件 gzip 231113→231350 B。包体读数来自 `test-results/v141-payload.json`。

## 功能与平台

P4 专项核对完整纯编译器的 14,006 条来源位置。真实 Worker 保留 7000 行 IR，回传准确总数和前 200 条。候选推进到 `l1` 后，运行证据与资源计划哈希都匹配候选缩进 JSON 加 LF，证据面板将候选标为与当前工程不同，当前工程导出字节逐字节一致。取消、迟到回复、超时替身、重试及一次撤销仍由原 P4 场景覆盖。

本地 `npm run check` 执行 381 项 Node，377 通过，四项在创建符号链接时返回 `EPERM`，零跳过。补跑的 Python 兼容测试 6 项、schema 同步、200 份来源、五样例结构和本仓工作流清单检查通过。工作流 Python 回归 7/8，另一个符号链接夹具返回 `WinError 1314`。符号链接断言由 Linux 同提交全量运行。

浏览器、编辑器、性能与来源哈希的本地最终状态见 [机器记录](v1.4.1-validation.json)。同提交 Linux Engine、Windows Chromium 专项与原生 WebView2 文件 IO 和完整重启的结果另存 `test-results/v1.4.1-cloud.json`。Windows CI 的系统对话框使用预设路径。五个技术样例的提交锁定 QA 与原始证据汇总至 `test-results/v1.4.1-delivery.json`，内容与正式发布沿用独立门禁。
