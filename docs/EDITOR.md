# VN Engine Studio 1.0.0

可视化编辑器与播放器共用 `EngineProject`、真实状态机、资源清单、调度与渲染，没有另一份预览用剧情逻辑。1.0.0 增加作者异步操作保护，更新与兼容范围见 [版本说明](RELEASE-v1.0.0.md) 和 [1.x 约定](V1_COMPATIBILITY.md)。

```bash
npm ci
npm run demo
# 打开 http://127.0.0.1:4173/editor/
```

## 作者工作流

1. 新建视觉小说、聊天叙事、条件剧本或调查工程，也可打开引擎独立样例或自己的 JSON / `.vnproj`。
2. 在节点图选择场景，编辑台词、出口、分支目标和资源绑定。拖动节点调整布局；键盘选中节点后 Alt + 方向键也可移动。撤销/重做保存最多 80 次命令；输入框内保留原生文本撤销。
3. 在资源清单登记 ID、类型、相对路径和许可，绑定包含这些路径的资源根目录。浏览器预览使用所选文件的临时 blob URL；工程里的相对路径不会被替换。Windows 通过原生文件桥读取清单文件。
4. 在实际引擎里从头试玩。编辑后自动重新启动预览，预览存档只保存在内存中，不写入正式游戏存档。错误状态保留上次有效预览，并禁用运行数据导出。
5. 在“路线测试”从头手动录制，完成录制添加实际步骤与期望；可编辑用例、撤销、独立 Worker 执行 / 取消和导出绑定工程的报告。工程修改会使录制和旧结果失效，失败可定位节点；完整规则见 [路线 QA](ROUTE_QA.md)。
6. 保存 `.vnproj` 保留工程、路线用例和节点布局；导出 `.json` 得到原生 `EngineProject`，不含编辑器字段，可直接使用 `npm run build:game -- project.json build/my-game`。

浏览器的保存使用下载；本地草稿独立保留。Windows 使用原生保存对话框及原子 JSON 替换，另存时复制已绑定的引用资源，并拒绝覆盖目标目录中内容不同的资源。手动选对话框是用户行为，CI 使用预设路径检查相同的文件读写处理链。

## 玩法和数据

| 类型 | 属性面板 | 高级 JSON |
| --- | --- | --- |
| VN / 聊天 | 节点、台词、聊天/通话呈现、选择、数值变化、连接、场景/台词演出绑定 | 章节续接、条件变体与完整工程字段 |
| 条件剧本 | 变量目录 / 类型 / 初值 / 边界、变量引用改名 / 删除保护、有序赋值 / 累加、台词、选择、组合条件 / 末项兜底、演出与媒体 | 完整变量元数据、效果数组和条件路由 |
| 调查 | 章节新增 / 入口 / 排序 / 改名 / 删除保护，节点正文、证据目录、条件、收集 / 隐藏 / 清空、同章连接、结果 | 热点、谜题、录音元数据和完整约束 |
| Rain 兼容 JSON | 原格式打开、诊断、实际自研 VM 试玩和原格式导出 | 使用工程 JSON 编辑；本版不把兼容数据转换成另一种格式 |

“章节与变量”面板为条件剧本提供变量目录：数值 / 布尔初值、可选上下界、引用定位、原子重命名与删除保护。改名会同步组合条件、选择效果和路线期望；保留作者扩展元数据。已有引用时不能直接改变类型，空白与非有限数字会拒绝并恢复输入。选择效果在节点属性中按顺序执行，支持数值累加和数值 / 布尔赋值、排序与撤销；高级 JSON 保留。

条件路由按已声明变量提供数值 / 布尔编辑，条件以 AND 组合，可同时声明同一数值的 `eq` 与 `gte`；按从上到下的首个匹配执行，末项无条件兜底不能移走。导入的复杂字段不在打开表单时自动改写。

调查节点内的“本章证据目录”可编辑标题和内容、添加证据，并重命名全部同章引用和能明确归属的路线期望。录音等元数据保留；含引用的证据不能直接删除。跨章路线期望没有准确 `lineId` / 唯一 `sceneId` 时，重命名会拒绝并保留原工程。节点同时要求 / 排除同一证据，或动作同时清空 / 收集，会定位冲突并禁止导出，可撤销修复。高级证据 JSON 保留人工修复入口。

调查的“章节与变量”面板可以添加章节、编辑标题和入口、调整顺序、定位入口节点并重命名章节。改名同步演出键、布局、章节动作、结局收藏 / 真路线和路线期望，删除有外部引用的章节会被拒绝。排序会改变开场和解锁，旧路线结果失效并须重跑；未连接的入口会由真实状态机报错并阻止导出，可撤销修复。工程包含剧情回看快照时，章节 ID / 排序 / 删除控件会明确锁定，先移除回看点，修改后重新录制；不猜测不透明存档内容。

多人协作与自定义插件界面留待后续。兼容适配器的动态结局不由静态连线推断，调查合法循环仍由库存联合状态检查。已有发行作品改 ID 或故事顺序仍需独立设计 storyVersion 和存档兼容方案。

## 制作与审阅

0.7 的工作台提供简报、角色、节拍、六类任务和依赖 / 输出关联，实际图片 / 字体 / 音频、哈希 / 使用处、主题及目标反馈。派生 ID 定位原字段，Rain 选择原格式 JSON 字段，不自动分配 ID。反馈独立保存 review.json，有自己的撤销 / 重做 / 草稿；修复说明、复验声明与重开分别记录，源 / 字节变化后显示过期。

Windows 通过受限文件桥打开 / 原子保存，检测外部修改；浏览器用真实文件导入 / 下载。换项目、离开、隐藏或 dispose 清理媒体。项目 / .vnproj / 玩家数据不含反馈，需另存，详见 [R3 约定](ITERATION_DEVELOPMENT.md)。

## 数据保护与限制

- 导入先解析，失败保留当前工程。命令原子提交，异常不污染历史；删除节点保留入站分支，暴露断链供修复。
- 重命名节点同步入口、入站引用、场景演出键和布局。已有发行作品重排台词或改 ID 仍需单独设计存档兼容方案。
- 草稿保存应用后的工程及 JSON 面板尚未应用的文本；恢复后本地资源目录需要重新授权绑定。草稿存储失败会明确提示保存文件。
- 显式资源绑定检查 ID、类型、路径、字体许可；绑定目录后再检查实际文件是否齐全。绘制资源失败仍由播放器处理，不冒充完整美术验收。
- 作者文本按文字显示，JSON 不执行 JavaScript。预览消息核对来源窗口和同源地址；Windows 文件桥仅允许可信编辑器顶层文档访问。
- 此工具仅编辑当前工程；四个正式游戏的迁移保持用户主动发起的独立步骤。

```bash
npm run build:studio -- build/studio
npm run test:editor
```

独立 Studio 包含编辑器、自研运行模块、本地样例、字体和许可。Windows 宿主直接使用同一份内容，见 [WINDOWS.md](WINDOWS.md)。

## 0.8 AI 模拟终审

制作与审阅 → 验证状态提供独立 acceptance.json 的打开 / 保存、证据目录绑定、当前源 / 素材核对与问题转入反馈。正文修改使旧结果过期；撤销还原精确源后可重新核对。离开子面板、换工程或 dispose 会取消旧读取，导入错误保留已载入文档。

终审文件、反馈、玩家工程分别保存；合成 PASS 截图只证明协议。独立 Studio 的作用域离线缓存能在子目录断网新页打开，预览使用真正的 preview.html。实际审核与平台范围见 [R4 验证](VALIDATION-v0.8.0.md)。
