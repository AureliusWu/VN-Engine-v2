# v1.0.0 更新方案

日期：2026-10-30。基线：`a6b54f68412c91a7e64d0a88149a216595f61cdd`（0.8.2）。目标是交付可验证的 1.0.0 引擎与明确的 1.x 兼容边界。

R7—R10 上轮仅完成预检，未实施或发布。本次将其收敛为以下四个阶段，不把预检记作四轮已交付，也不自动迁移四个正式游戏。

| 阶段 | 执行内容 | 验收标准 |
| --- | --- | --- |
| 作者状态（R7 预检） | 审阅保存快照、审阅后选优先与编辑保护、异步目录绑定隔离 | 旧保存不误标新反馈；旧打开 / 绑定不覆盖后续编辑或新工作区，失败与取消保留数据 |
| 阅读交互（R8 预检） | 存档展开确认及取消覆盖后的焦点恢复 | 原槽位字节不改，确认 / 取消后立即 Escape / Tab 可用，初次打开和外部焦点行为不退化 |
| 渲染恢复（R9 预检） | 系统减少动态与场景效果一致、临时图片失败在下次访问重试 | 初始和动态 reduce 均禁止 / 取消 flash/fade/shake；失败不造成逐 tick 请求风暴或旧请求复活 |
| 兼容与交付（R10 收敛） | 存档 key / envelope 槽位一致性，1.x 入口与格式契约，平台矩阵和发布记录 | 错位槽位 invalid 且保留原文；合法旧数据仍可读；完整核心 / 浏览器 / Studio / Windows 原生与最终 main CI 通过 |

## 实施约束

1. 先保留旧码失败，新增确定性回归，再修最小必要逻辑；操作身份逻辑与界面定义保持清晰边界。
2. 保持项目 / Studio schema 1、SaveEnvelope schema 2、既有开发协议与故事身份；引擎版本变更不改 game / storyVersion / 存储 namespace。
3. 顺序构建，执行 `npm run check`、完整 `npm run test:browser` 和 `npm run test:editor`；本机权限限制如实记录，CI 不跳过失败。
4. 源码提交后按真实 SHA 重建四样例，验证路线 / 文件 / 解码 / 独立包；正式内容的 BLOCKED / DRAFT 继续保留。
5. npm、lock、源码、Windows 版本统一 1.0.0；更新 provenance、CHANGELOG、兼容说明、发布说明和机器验证记录。
6. PR 完整检查通过后合并，再核验实际 main 的 Engine / Windows CI。最终本地与远端一致、工作区干净、仅保留 main，不强推。

1.0.0 是引擎交付版本，作品内容终审、实体设备、签名发行和公共包发布分别记录。本次不自动发布 npm 或创建 GitHub Release / tag；可下载构建产物由经过 CI 的工作流提供。
