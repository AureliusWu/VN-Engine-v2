# 0.2.1 引擎优化

日期：2026-10-25。仅修改 VN-Engine-v2。用户明确要求先优化引擎，四作迁移留到最后，并且只在用户主动、明确提出后执行；该约定已写入 AGENTS、路线和兼容文档。

## 已复现并修复

新增稳定性回归在 0.2.0 上复现了以下六项失败，修复后通过：

| 问题 | 修复 |
| --- | --- |
| 关闭再开启语音，同段录音没有恢复 | 静音时清理访问身份，重新启用后重新绑定当前段落 |
| 快速开关面板，迟到的 suspend 使页面继续阅读却静音 | 串行处理音频图状态，操作完成后再核对最新意图 |
| 音效不跟随实时音量、关闭后仍继续 | 更新活动音效音量；关闭与结束时立即释放播放器 |
| 声音工厂抛错使挂载/推进异常 | 失败清理并释放自动阅读锁，文字继续可用 |
| 语音通知期间重入切段，最新段落设置被丢弃 | 只保留并及时消费最新状态，旧访问不能补播动作 |
| 外部修改资源清单的嵌套许可或 baseURL 会影响内部 | 元数据返回独立副本，部署基址保持私有，URL 预先解析 |

音频图增加无进展检测：如果宿主的 resume/suspend 已完成却没有改变状态，报告一次失败而不陷入重试循环。

## 刷新成本

新增 `RuntimeSession.getView()`：同一状态复用只读视图，文字变化时复用已经冻结的 frame。内置 DOM/媒体宿主改为读取该视图，文字逐字累积，Segmenter 按会话复用。原 `getSnapshot()` 继续返回可修改的独立副本，存档格式不变。

媒体只在访问、暂停或声音设置变化时重配，文字打字与透明度变化不再重复重配音频。聊天保留当前气泡与文本元素，按帧合并滚动请求；读者上翻后不会被逐字更新拖回底部。

[性能记录](runtime-performance-0.2.1.json) 对照相同段落/文书，7 轮预热后采样：旧内部读取路径在测量期间分别调用 structuredClone 35000 / 7000 次，新只读路径为 0 次。输出文本校验和一致。时间仅为本地微基准，不能推算实际 FPS、完整游戏速度或其他硬件表现；公共副本 API 仍会复制。

```bash
npm run benchmark
```

## 演出与资源生命周期

- 后台、隐藏与面板暂停同步暂停正在运行的演出；恢复只继续原动画。
- 减少动态效果立即清理当前动画；读档仍不补播历史动作音效或震屏。
- 挂载失败释放会话计时器与半成品 DOM；销毁清理滚动帧、图片探测和订阅。
- 文本补全后，即使仍有剧情停顿，操作控件也同步更新。

新增 9 项 Node 稳定性检查与 4 项真实浏览器检查；总计 62 项 Node、6 项 Python、22 项浏览器场景。完整构建、离线重开与独立作品打包继续回归。未改变四作依赖、运行链、原文或存档。
