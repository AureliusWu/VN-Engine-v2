# v1.4.5 制作计划引用诊断验证

日期 2026-11-06。基线 `5fc6adf55fe0021bda108ecb48599cf3609b3653`。开源源码、论坛案例与范围见 [升级计划](PLAN-v1.4.5.md)。

## 同机性能

Windows x64、Node 24.14.0、AMD Ryzen 5 3600。每版固定三轮独立 Node 进程。两版使用相同工程、预热和批次数，分别调用 `creativeDiagnostics()` 和 `EditorModel.diagnostics()`。大工程含 1536 块、3072 句、192 个节拍和 128 项任务。无目标对照保留同一工程的任务与依赖，只移除目标引用。表中为中位 / 最慢，单位毫秒。

| 工程与范围 | v1.4.4 | v1.4.5 | 中位变化 |
| --- | ---: | ---: | ---: |
| 12 块、32 目标，制作诊断 | 0.255 / 0.264 | 0.249 / 0.250 | −2.61% |
| 12 块、32 目标，完整诊断 | 0.568 / 0.577 | 0.556 / 0.558 | −2.07% |
| 1536 块、4352 目标，制作诊断 | 122.286 / 144.631 | 19.752 / 19.835 | −83.85% |
| 1536 块、4352 目标，完整诊断 | 211.606 / 214.224 | 49.894 / 50.290 | −76.42% |
| 1536 块、无目标，制作诊断 | 14.864 / 15.551 | 13.878 / 14.012 | −6.63% |
| 1536 块、无目标，完整诊断 | 37.595 / 37.744 | 35.138 / 35.742 | −6.53% |

逐轮核对了工程哈希、有序诊断和输入完整性。所有中位数通过门槛。数据范围为 Node 中的同步诊断夹具。原始基线、最终样本和对照分别保存在 `test-results/v145-baseline-creative-diagnostics.json`、`v145-after-creative-diagnostics.json` 和 `v145-creative-diagnostics-comparison.json`，早期候选样本另存。

## 兼容与平台

新增两项回归覆盖章节与节点键、歧义计数、独立台词存在性、任务重复 ID 首定义、环路和诊断顺序。直接诊断回归覆盖稀疏节点数组。初次稀疏夹具走 Studio 的 JSON 入口，被该入口拦截，随后改用直接 API。原始错误日志单独保留。

Windows 本地 Node 384/388，四项符号链接夹具创建返回 `EPERM`，零跳过。兼容 Python 6 项、schema、200 份来源、五样例结构和引擎清单检查通过。工作流 Python 7/8，符号链接夹具创建返回 `WinError 1314`。Linux 工作流执行这些用例的原断言。

完整浏览器、编辑器、逐轮测量及源码哈希见 [本地机器记录](v1.4.5-validation.json)。推送后的同一提交 CI、原生 WebView2 和五样例提交锁定 QA 证据见 `test-results/v1.4.5-delivery.json`。
