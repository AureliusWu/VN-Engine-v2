# v1.5.1 Studio 恢复保护验证

日期 2026-11-06。基线为公开正式版 `v1.5.0`（`f641a57878f9bddbbc191818ebb2287de4efca87`）。[计划和社区资料](PLAN-v1.5.1.md)记录了旧版的真实 Chromium 复现和样本范围。

| 恢复场景 | v1.5.1 回归证据 |
| --- | --- |
| 从有未保存编辑的 A 导入便携 B | A 有无旧草稿时均同步保存最新编辑，清理旧计时器，重载仍可恢复 A；编辑 B 后写入 B。干净工作区且槽为空时仍自动保存 B，保持原始 JSON 字节。 |
| 接收端制作面板已筛选 | 实际下载和导入 `.vnrecover`。恢复指定的任务视图和空白待提交字段，修正 ID 后可保存工程。 |
| 坏 UTF-8 或 `assets: [null]` | 真实文件选择后拒绝导入，保留当前工程、绑定目录、已挂载预览及原始运行 JSON。合法 BOM 与 U+FFFD 可读。共享工程 reader 仍允许不完整的素材对象进入诊断。 |
| 空反馈目标的待修 Rain | 恢复后显示原说话者诊断；在 JSON 面板修正后可导出并实际试玩。 |

本地使用真实 Chromium、独立工作区和可控草稿计时器。Node `check` 受四项 Windows 符号链接夹具 `EPERM` 限制；工作流 Python 有一项同类 `WinError 1314`。其余门禁分别执行。精确计数、失败原文索引、测试报告和文件 SHA-256 见 [机器验证记录](v1.5.1-validation.json)。

推送后，同一 `main` 提交的 Linux 核心与浏览器、Windows WebView2 与完整进程重启证据见本地 `test-results/v1.5.1-cloud.json`。自动化覆盖预设路径文件 I/O；系统对话框人工操作、实体设备和内容验收各自独立。公开正式下载仍为 v1.5.0。
