# v1.4.2 Studio 预览来源验证

日期 2026-11-06。基线为 `a476ed0a609941583cc3cf1b528ad7c5ea6e6287`。开源实现、论坛讨论和方案见 [升级计划](PLAN-v1.4.2.md)。

## 基线复现

在原版 Studio 和真实 Chromium iframe 中，未应用的 DSL 候选沿用了当前工程的作品及版本 ID，旧版允许把候选第 2 句的位置写入当前工程。关闭自动预览后，在保留旧试玩的同时把工程选择改为 `new-choice`，旧版仍能保存 `old-choice` 的回看起点。延迟原生 iframe 回复的测试也复现了旧回看跨刷新写入、旧证据和资源计划在同源新预览中显示为当前，以及旧录制确认将 `old-choice` 写入新工程的路线用例。

基线记录见 `test-results/v142-baseline-repro.json` 与 `test-results/v142-baseline-preview-races.json`。受控测试只改变真实 iframe 消息的交付顺序。

## 修复验证

| 场景 | 实际验证 |
| --- | --- |
| 回看起点 | 拒绝未应用候选和同身份旧工程。刷新取消等待。超时后在同一 revision 重试，旧回复无法结算新请求。当前工程能保存并导出真实推进后的回看起点。 |
| 路线录制 | 工程编辑后交付旧挂载确认，录制保持关闭。重新录制后，实际点击的 `new-choice` 写入用例。既有路线 QA 和导出检查也通过。 |
| 运行证据 | 同源重刷拒绝迟到报告，旧的已完成报告保留原会话及来源状态。候选证据继续按其实际 SHA 标记与当前工程的关联。 |
| 资源计划 | 同源重刷使旧计划过期并禁用定位，启用新预取预算后迟到旧计划无法覆盖。重新采集恢复定位。 |
| 哈希完成窗口 | 对父页的两次 SHA 计算分别进行受控延迟，在真实校园预览刷新后释放，两个旧采集均未提交。此专项记录见 `test-results/v142-capture-hash-check.json`。 |

工程模型和精确来源文本在派发时绑定到挂载 revision。来源内容未编辑时，普通工程继续使用原始导入文本，编辑后使用当前序列化文本。候选依旧按需生成来源文本。requestId 仅用于 Studio 的消息关联。回看、存档、路线用例和报告保持既有格式。
