## 目标

这个自研 Galgame 引擎主要交给 GPT / Codex 等开发 Agent。R1 已提供统一 SDK / CLI；R2 补齐美术、音乐、UI、音效、文本、剧情的创作组织、素材接入、约束检查和实际呈现。人提出要求与试玩验收，Agent 通过接口完成生产、导入、绑定、检查、预览和构建。目标版本 0.6.0。

## 边界

只修改引擎及独立技术样例，四作与 RESET 的剧情、正式资产、存档和运行链保持独立，本轮不迁移。继续使用同一作者模型、解释器、校验、DOM / 媒体宿主和打包链，不引入替代引擎。保留 R1 vn-agent-v1 调用和项目 / EditorDocument / Save schema 1；新内容以明确版本的兼容扩展 vn-creative-v1 声明。模块导入无设备和业务 IO 副作用。

## 必须实现

1. **创作上下文**：可验证的 production schema，组织简报、角色设定、剧情节拍和 art / music / ui / sfx / text / story 六类任务。任务有稳定 ID、依赖、目标节点 / 台词、输出资源、生成提示词与实际来源；循环依赖、悬空引用和非法状态可定位。制作进度不等于人工审核通过。
2. **可发现的读取与编辑**：沿用 capabilities / inspect / refs / apply，支持按文本、角色、节拍、制作任务、UI 和资源范围有界读取；新增编辑使用稳定 ID，保留扩展字段。重命名同步相关制作引用，删除保留引用保护；一次批次允许暂时不完整，最终共享校验必须通过。
3. **素材探测与导入**：通过统一 CLI / Node SDK 探测本地图片、字体、音频等实际字节，返回 SHA、解码状态、尺寸 / 时长 / 声道等。批次可导入已知 SHA 的素材，复制到项目内不可变的内容寻址路径，再绑定 asset / cue。提供 dry-run、提交前冲突复核、请求回执和中断恢复；不覆盖已有不同内容。项目写入失败时保留原源文件，若已留下未引用素材，必须如实列出，不声称多文件数据库事务。
4. **美术与来源**：记录素材用途、提示词、生成 / 原创 / 授权来源及哈希。实际生成独立场景与角色插画并导入；不以几何占位图冒充完成的插画。生成或绑定成功不能自动把 DRAFT / REVIEW 提升为人工 READY。
5. **音乐与音效**：支持按既有 music / ambience / sound / voice 语义绑定，复用真实播放器；探测实际解码、采样率、峰值 / RMS / 静音和循环边界等技术事实。样例包含原创可播放配乐和音效，明确其生成 / 程序合成来源；实际播放、暂停 / 恢复和一次性音效有浏览器证据，不把解码成功等同听感验收。
6. **UI**：提供类型化、可发现、可验证的项目 UI 主题，支持预设与有限颜色 / 密度等令牌，真实应用到播放器、Studio 预览、Agent 预览和独立包。无自定义脚本 / 任意 CSS 注入，保留玩家设置优先级及键盘 / 窄屏可用性。
7. **文本与剧情**：提供稳定台词目录与剧情节拍映射，批量改写和引用检查；制作任务能关联角色、节点、台词、资源。提供机器可读的内容审查，识别未完成任务、空文本、过长文本、未绑定节拍 / 输出和潜在语音失效等问题；不伪称机器已确认文学质量或剧情一致性。
8. **协议与文档**：请求 / 响应 / 编辑 / production / UI schema 与代码一致，stdout 始终 JSON、错误码稳定、有定位、有预算。新增能力只在实际实现与验证后声明；保留 R1 冲突、去重和恢复语义。
