# v1.4.3 Studio 大图诊断验证

日期 2026-11-06。基线为 `5e3f0c952c7584bf959758fcf1228aab3ab93ae7`。开源对照、论坛讨论和方案见 [升级计划](PLAN-v1.4.3.md)。

## 同机性能

Windows x64、Node 24.14.0、AMD Ryzen 5 3600。前后各固定三轮，每轮使用独立 Node 进程和相同夹具、预热及批次数。完整诊断直接执行 `EditorModel.diagnostics()`。图诊断拆分使用编译模块的内存探针，涵盖图提取、重复和断链检查及可达性。各阶段单独计时，单位毫秒，表中为中位 / 最慢。

| 夹具与范围 | v1.4.2 | v1.4.3 | 中位变化 |
| --- | ---: | ---: | ---: |
| 12 节点、14 边，完整诊断 | 0.1529 / 0.1587 | 0.1473 / 0.1525 | −3.7% |
| 4096 节点、5119 边，仅图提取 | 3.163 / 3.441 | 3.490 / 3.492 | +10.34% |
| 4096 节点、5119 边，图诊断 | 159.723 / 239.937 | 4.882 / 5.184 | −96.9% |
| 4096 节点、5119 边，完整诊断 | 173.273 / 178.166 | 24.021 / 25.639 | −86.1% |

大图单独提取增加 0.327 ms，超过 10% 提示阈值，综合记录为 WARN。图提取源码未改，三轮样本不足以区分持续回退和波动。全部读数均保留。性能结论限于此次 Node 夹具和同步诊断，不作为浏览器端到端或玩家运行耗时。

原始记录为 `test-results/v143-baseline-diagnostics.json`、`v143-after-diagnostics.json` 与 `v143-diagnostic-performance-comparison.json`。内存原型的探索测量单独保存在 `test-results/v143-exploratory-graph.json`。

## 兼容与平台

配对夹具的输入和图输出哈希一致。有序诊断逐项相等。新增两项回归覆盖多入口、不同章节同名节点、循环、平行边、不可达与断链顺序，以及动态适配的明确断链和单条动态路由提示。可达性按有效出边计算。资源、内容及实际运行验证继续走原入口。

本地核心执行 383 项 Node，379 通过，四项符号链接夹具创建返回 `EPERM`，零跳过。另行运行的兼容 Python 6 项、schema、200 份来源、五样例结构和引擎清单检查均通过。工作流 Python 7/8，另一项符号链接创建返回 `WinError 1314`。Linux CI 执行这些夹具的原断言。

完整浏览器和编辑器、各阶段性能数据与提交文件哈希见 [本地机器记录](v1.4.3-validation.json)。Windows 在已有工作流内单独执行 `tests/editor.test.mjs`，并核对 WebView2 首跑、文件操作和完整重启。推送后的同提交 CI 见 `test-results/v1.4.3-cloud.json`，五样例提交锁定 QA 和交付证据见 `test-results/v1.4.3-delivery.json`。
