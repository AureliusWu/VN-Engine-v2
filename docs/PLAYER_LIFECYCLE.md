# 启动与标题流程

`EngineProject.titleScreen: true` 让 `mountGame` 先显示标题；缺省或 false 保持原来的直接阅读。Studio 工程区“启动界面”可选择标题菜单，支持预览、撤销与原始运行数据导出。

标题提供开始新游戏、继续最近有效进度、读取存档、阅读设置，以及已配置的 CG / 结局收藏。Web 不模拟退出浏览器；Windows 使用原生窗口的关闭入口。标题状态暂停调度和媒体，隐藏正文舞台，未开始时不写 Auto、不累计结局 / CG。设置和收藏返回标题，Esc 不会绕过标题开始剧情。剧情回看继续使用独立会话。

新游戏会重建临时剧情状态，保留手动 / Quick、收藏、设置和独立已读记录；Auto 在明确开始后更新到新进度。新游戏与返回标题都有确认 / 取消；取消不改路线或存档。返回标题保留本次会话，“继续当前阅读”回到准确位置。重新打开应用后则通过 Continue / Load 恢复已保存的位置。

Continue 在独立运行时按保存时间寻找真实可恢复的候选：Auto、Quick、Manual；相同时间按此顺序，再按手动槽号。损坏、错槽、不可达候选保留原字节并跳过。点击时重新查询，不依赖先前预览。空槽和暂时不可用的存储有明确反馈。

旧 Auto 在首次挂载时保持原字节，包括损坏或暂时不可读的数据；不再由开场立即覆盖。直接阅读项目只有空 Auto 才初始化开场存档，启用标题的项目则等明确开始后写入。翻页、剧情动作、读档或明确新游戏仍按既有规则更新 Auto。

`RuntimeSession.restart()` 等核心 API 继续直接执行；确认属于 DOM 玩家界面。只使用核心的自定义宿主可通过 `initialPause` 在第一帧前暂停，并负责自己的开始 / 取消流程。

## 跨重启已读记录

`mountGame().readProgress` 使用独立键 `vn-engine:{game}:read:{encoded storyVersion}`，不嵌入普通存档、备份、Meta 或设置。标记为台词 ID、实际发言人、最终条件文本的规范 JSON 元组，使用准确字符串比较，不将弱哈希碰撞当成已读证明。版本变化隔离；同版本改文本或发言人也不会匹配旧标记。旧版本记录不自动删除或迁移。

会话在完整显示且没有暂停 / 隐藏时记录。标题、后台和面板中因设置变成全文不会先记已读；实际恢复阅读才记录。导入的历史不会批量进入持久标记；当前句完整且可见时可记录。独立回看不连接该存储，状态回滚不调用持久标记操作。Skip 仍在进入一段时判断原先是否已读，遇到未读或选项停止。

每个游戏 / 版本最多 10,000 条，并有文本总量与 2,000,000 UTF-8 字节上限。超过容量淘汰较旧标记，只会使旧段落需要重新阅读。最多 250ms 合并写入；暂停、pagehide 与实例 dispose 会刷新已完成的读记录。`flush()` 可供自定义宿主显式调用。先合并其他写入者的最新记录再保存；StoragePort 没有跨标签页事务，不承诺并发写入全程原子性。

损坏、错游戏 / 版本或重复 / 无效标记保持原字节，不自动覆盖；当前会话仍保留自己的已读状态。存储不可用或配额失败时允许继续阅读，并保留待写记录以供重试。异常终止且 pagehide 未发生时，最后一个写入批次可能丢失；这不会改动剧情存档或收藏。
