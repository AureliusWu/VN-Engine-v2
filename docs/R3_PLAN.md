## 目标

让同一作品可以反复完成“提出修改 → 判断影响 → Agent 修改 → 人试玩并反馈 → 修复 → 复验 → 重新构建”。人能在 Studio 查看六类任务、素材和具体问题；Agent 能读取结构化反馈并通过已有 SDK / CLI 修改。每次结果都对应实际工程与素材，旧预览、旧审阅和旧测试不会冒充新版本已经通过。

R3 优先解决 R2 之后的内容迭代和审阅体验。大工程全面性能改造、跨故事版本存档迁移、联网协作与新渲染后端留作后续独立规划。

## 必须保留的边界

- 只修改引擎和独立样例；四作与 RESET 的剧情、正式素材、宿主、依赖和玩家数据不迁移。
- 保留自研解释器、作者模型、渲染 / 媒体和打包链；不引入替代引擎或第二套作者规则。
- 保持 vn-agent-v1、vn-creative-v1 既有调用兼容，项目 / EditorDocument / Save schema 1 不变；新增能力以显式版本的数据和 schema 声明。
- game、storyVersion、稳定台词 ID 和存档命名空间分别维护；普通内容修改不自动重编号、升故事版本或迁移旧档。
- 作者审阅数据不进入玩家 Save / Meta / 已读，也不默认装入独立作品。模块导入不执行设备或网络 IO。
- DRAFT / REVIEW / READY、任务制作状态、机械检查和人工终审分别记录；Agent 标记“已修复”不等于人已验收。审核声明真实性不由机器自动认证。
- 本轮已获实施授权，依次完成 A / B / C；完成 R3 后停止，不自动开展下一轮。

## A：内容目录、修改影响与审阅数据

1. 统一内容目录，覆盖 narrative / chat / script / investigation / Rain 的主要台词、条件文本、选择 / 动作文案及 Rain 回应；区分内容种类、原字段路径和显式 / 派生身份。原来没有显式 ID 的内容只报告派生位置，不擅自重编号。
2. 对语音检查复用实际 cue 优先级，覆盖默认、场景 / 节点、台词继承及文本变体；无法证明匹配时给出定位和 UNVERIFIED，不猜测已适配。
3. 扩充既有 dry-run / inspect / refs，报告 before / after 源 SHA、修改实体、受影响的任务 / 资源绑定、潜在失效语音、需要重新预览与复验的范围。动态 presentation 或缺少证据的影响明确保留未知。
4. 引入版本化的作者审阅文档，建议独立 `review.json`，绑定 game、storyVersion、工程源 SHA、相关素材 SHA 和问题目标。它与项目分别保存；文件宿主复用预期哈希、锁、回执和原子替换，不宣称两个文件组成数据库事务。
5. 反馈有稳定 ID、问题类别、目标、意见、修复说明和操作者 / 时间记录；区分“待处理、已修复待复验、已复验、重开”。源或关联素材变化后重新计算有效性，过期记录必须显式显示，不能继承为本次 PASS。
6. 在同一 vn-agent-v1 下增加有界反馈读取 / 编辑与影响分析能力。具体命令和 schema 在阶段 A 实现时固定；本计划不将拟议接口写入现有 capabilities。

审阅意见属于作者工作数据，不自动写成 releaseEvidence 的人工 PASS。正式构建继续执行现有美术 / QA / 路线门禁；旧格式记录保留其原契约，不能冒充新绑定已经验证。

阶段 A 不做“只跑受影响路线即可发布”的优化。影响报告用于定位和安排修复，完整路线回归仍是最终验收要求；旧报告按源 SHA 判断是否有效。

## B：Studio 制作与审阅工作台

| 面板 | 必须支持 |
| --- | --- |
| 制作上下文 | 查看 / 编辑简报、角色、节拍和六类任务，按种类 / 状态 / 角色筛选，显示依赖和断链 |
| 素材查看 | 按 ID、用途、状态和实际哈希查找，显示来源与使用位置；实际图片 / 字体预览，音乐 / 环境音 / 音效试听及停止 |
| 主题 | 用有限控件编辑已有预设、颜色和密度，实时调用同一播放器；保留玩家字号 / 高对比优先级 |
| 问题与反馈 | 从台词、节点、任务或素材进入具体问题；显示源版本、当前有效性、修复说明和复验状态，支持重开 |
| 验证与交付 | 显示机械 review、路线、实际预览和人工状态各自结果；保存 / 导出作者审阅文档，运行数据导出保持干净 |

所有编辑复用共享作者命令和校验，支持撤销 / 重做、错误保留原数据及扩展字段；不在 Studio 另写一套剧情或任务规则。预览和试听的暂停、取消、换项目及 dispose 必须清理媒体，不污染玩家存储。

浏览器支持实际文件导入 / 导出与重新打开；Windows 通过受限原生文件桥打开 / 保存作者审阅文件，并验证完整进程重启。系统对话框人工操作和 CI 预设路径分别记录。桌面和 390px 均检查键盘、焦点、文字与页面溢出。

## C：独立样例与真实迭代

复用 R2 书店样例及已记录来源的插画、程序音乐和音效；新修订使用独立工程与存储命名空间。SDK 和 CLI 分别完成同一套流程，项目修改全过程不依赖人工打开 Studio 改 JSON。

| 轮次 | 实际修改 / 操作 | 必须观察到的结果 |
| --- | --- | --- |
| 初稿 | 打开简报、角色、六类任务和现有真实素材，运行路线与桌面 / 窄屏预览 | 建立带工程 / 素材身份的初始记录；素材仍为 DRAFT |
| 修订一 | 改写台词与一个分支，新增或修改对应反馈 | 影响报告定位目标；旧机械结果和相关审阅显示过期；新路线 / 存读档复验真实执行 |
| 修订二 | 替换一个素材或演出绑定并调整主题 | 旧引用 / 哈希 / 视觉审阅不可冒充当前结果；旧内容寻址文件不被覆盖；实际呈现和播放更新 |
| 修复与重开 | Agent 写修复说明，人通过工作台查看、复验或重开问题，保存后重新打开 | “已修复”和“已复验”有区别；记录持久化，源冲突不会静默覆盖 |
| 技术交付 | 重新构建，子目录部署，断网后新页重开 | 展示最新正文 / 素材 / 主题；不夹带作者反馈文件；人工缺项仍阻断正式发行 |

自动测试中若需要模拟人工复验，必须明确标记为合成夹具，不能写成该样例已经通过真实人耳、文学、美术或实体设备终审。
